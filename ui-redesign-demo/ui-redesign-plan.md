# 第一部分：功能评审 & 梳理报告

## 1. 产品定位

甜途不是单纯的“旅行攻略 App”，而是一个以 **Travel（旅行）** 为内容主轴的个人旅行记忆空间：

- 记录：按天写行程、回忆、照片与花销。
- 整理：自动生成旅行画册、时间线与旅行档案。
- 回看：地图足迹、数据看板、纪念日与搜索。
- 分享：旅行圈、公开旅行故事、点赞评论收藏。
- 协作：情侣 / 朋友 / 家庭 / 多人空间，按角色共同编辑。
- 留存：离线记录、自动同步、JSON / Markdown / 原图 ZIP 导出。

核心数据关系可以概括为：

```text
Travel
├── TravelDay
│   ├── ItineraryItem
│   ├── Memory ── Media
│   └── Expense
├── Album ── AlbumMedia
├── TravelPost（分享到旅行圈）
└── Space（可选归属）
```

- 头图、标题、日期、地点、同行者、旅行类型。

- 编辑 / 删除 / 归档。
- 待同步状态：本地创建但未上传时禁用写操作，并提供同步入口。

### 2.8 离线与同步（贯穿全应用）

- 移动端本地 SQLite 缓存。
- 在线优先直写，离线写入本地队列。
- 幂等键避免重复创建。
- 删除墓碑确保离线删除后不“复活”。
- 同步中心显示待上传内容。
- 离线时保留首页、旅行、相册、旅行圈等的本地快照。
- 待同步旅行禁止编辑，避免本地与云端状态分叉。
- 同步完成后自动刷新详情。

- 文章管理：Markdown 编辑、预览、文档导入、图片 / 视频上传、发布、分享到旅行圈。
- 旅行管理：天数、行程、花销。
- 相册管理：创建、关联旅行、批量上传。
- 纪念日、碎碎念、空间、成员、社交举报、审计日志。

### 3.2 用户主流程

1. **首次使用**：引导 → 注册 / 登录 → 偏好问卷 → 首页 → 新建旅行。
2. **记录一段旅行**：新建旅行 → 详情总览 → 按天添加行程 → 写回忆 / 传照片 → 记花销 → 完成归档 → 画册 / 时间线。
3. **浏览与互动**：旅行圈 Feed → 筛选 → 打开旅行详情 → 点赞 / 收藏 / 评论 → 关注作者 → 通知回访。
4. **多人协作**：创建空间 → 邀请伙伴 → 把旅行放入空间 → 成员共同编辑 → 查看空间动态。
5. **回看与留存**：首页足迹 → 地图 / 时间线 / 搜索 → 旅行画册 → 导出卡片或完整档案。
6. **离线场景**：离线记录 → 本地队列 → 同步中心 → 联网自动上传 → 详情刷新。

### 3.3 现有流程中的功能痛点

> 以下只讨论功能流程，不评价视觉好坏。

1. **记录动作过于分散**：新建旅行在底部中央，照片在详情相册 Tab，回忆在行程 Tab，碎碎念在独立页，花销在详情花销 Tab。用户想“记点什么”时，需要先判断它属于哪一类、再去对应页面。
2. **首页内容与任务混在一起**：首页同时承担足迹、画册、最近旅行、碎碎念、纪念日、进行中旅行。进行中的旅行是最高频任务，但容易被其他内容淹没。
3. **归档路径不自然**：“完成并归档”主要出现在首页进行中卡片，用户进入旅行详情后反而找不到完整的收尾动作。
4. **新建旅程与后续操作断链**：创建完成后虽然进入详情，但“先建空旅程、以后再补”的状态提示不够明确，用户容易以为没创建成功。
5. **照片语义重复**：旅行详情相册、全局旅行画册、纪念相册、像素相册、银河相册、照片留言，多个入口都叫“相册”，用户难以判断“我的照片到底在哪”。
6. **回忆与照片的写入成本不一致**：写回忆必须写标题；只想传几张照片时还要经过回忆表单（虽然详情相册 Tab 已提供独立上传，但入口仍不统一）。
7. **花销与行程的绑定不够显眼**：花销支持绑定到具体行程，但绑定后的联动价值（行程下显示费用、总览汇总）缺少明确引导。
8. **相册锁与模式切换缺少解释**：用户看到“像素 / 银河 / 画册”时，不知道它们是同一批照片的不同视图，而不是三套不同内容。
9. **空间页信息过长**：旅行、相册、规划、回忆、动态、成员、邀请、设置全部纵向堆叠；邀请入口只对主人可见，但成员不知道怎么加人。
10. **“我的”入口过深**：收藏、通知、同步、导出、偏好、主题、版本都收在抽屉或二级列表里，用户很难建立“账号中心”的稳定心智。
11. **离线状态只在小范围出现**：用户能看到“待同步”，但不知道哪些内容待同步、为什么编辑被禁用、怎样立即处理。
12. **社交动作的前置条件不清**：访客可以浏览但互动要登录；评论入口有时在卡片、有时在详情；关注、屏蔽、举报分散在多个位置。
13. **确认交互不统一**：删除旅行、退出空间、移出成员等有的使用系统确认框，有的使用动作面板，流程反馈不一致。
14. **深链与返回语义复杂**：Web 动态路由与移动静态壳查询参数并存，`/travel/[slug]`、`/travel/detail?slug=`、hash 锚点 Tab 等路径需要统一心智。
15. **空态与失败恢复缺少下一步**：部分页面只有“没有内容”的说明，没有直接创建 / 重试 / 去同步的入口。

## 4. 重构后的页面架构、导航与信息层级

### 4.1 核心原则

1. **以旅程为主轴**：所有内容最终都能回到某一段旅程；旅行详情是“总览 / 行程 / 相册 / 花销”的工作台。
2. **记录动作全局可达**：把新建旅程、写回忆、传照片、记花销、碎碎念收敛到一个全局“记录”动作中心。
3. **看与做分离**：首页负责“今天要做什么 + 最近值得看什么”；旅程负责“管理内容”；旅行圈负责“发现与互动”；我的负责“档案、协作与设置”。
4. **同一批内容只保留一个主入口**：画册是照片的主入口，旅行详情相册是当前旅程的上下文入口，纪念相册是私人相册入口。
5. **空间是协作层，不是另一套内容库**：空间聚合已有旅行 / 相册 / 回忆，保持内容唯一来源。

### 4.2 新导航结构

底部导航 5 个位置，其中中间是“记录”动作，不是独立内容 Tab：

```text
┌────────┬────────┬────────┬────────┬────────┐
│  首页  │  旅程  │  记录  │ 旅行圈 │  我的  │
└────────┴────────┴────────┴────────┴────────┘
```

- 首页：进行中旅程、快捷记录、足迹、纪念日、空间动态、最近内容。
- 旅程：搜索 / 筛选 / 地图 / 旅行列表 / 画册入口。
- 记录：打开全局动作面板。
  - 新建旅程
  - 写一条回忆
  - 上传照片
  - 记一笔花销
  - 碎碎念
- 旅行圈：推荐 / 最新 / 热门 / 关注 + 类型筛选。
- 我的：档案、统计、空间、内容入口、同步、设置。

### 4.3 重构后页面层级

| 层级 | 页面 | 说明 |
|---|---|---|
| L0 全局壳 | 底部导航、记录动作面板、Toast、Bottom Sheet、Dialog、安全区 | 所有页面共用 |

# 第二部分：UI 设计规范方案

## 1. 设计方向

关键词：**淡樱花粉、莓果撞色、照片优先、轻快青春、温柔怀念**。

视觉概念为「樱花糖纸 × 旅行手账」：浅樱花粉承担页面底色与主要操作，薄荷、晴空蓝、香芋紫、蜂蜜黄、蜜桃橙只做小面积撞色；旅行照片使用莓果酒红遮罩，让“青春活泼”和“旧日回忆”同时成立。撞色服务于信息层级，不做无意义的全屏彩色堆叠。

参考范式：

- **Vant 4**：Tabbar、Tabs、Cell、Popup、ActionSheet、Toast、Empty、Skeleton、PullRefresh 的结构与状态完备性。
- **NutUI**：表单、日期选择、步骤、上传与校验提示。
- **Varlet**：Material 式层级与动效节奏。
- **Fluent 2 / iOS HIG**：44px 触控、焦点管理、返回手势、安全区与大标题。

不在视觉上复刻旧项目的暖陶土、像素风、银河风；旧的“像素 / 银河”只保留为画册的可选视图能力，在新设计里以“画册 / 纪念相册 / 星图”重新表达。

- 樱花粉只用于主 CTA、选中态与关键数据，不把所有卡片铺成粉色。

- 图片上的文字必须使用固定白色 + 莓果酒红渐变遮罩，不依赖浅色 token，保证可读性。
- 深色模式保留同样的撞色语义，只降低背景明度与光晕饱和度。

## 6. 交互规则

### 6.1 触控与命中区

- 所有可点击元素最小 44 × 44px。
- 图标按钮视觉尺寸 20–24px，但命中区 44px。
- 列表行最小高度 56px。
- 相邻可点击元素间距不小于 8px。
- 底部操作条与内容之间保留 12px + 安全区。

### 6.2 导航

- 一级 Tab 切换不保留详情页栈；详情页隐藏底栏。
- 详情页左上角返回 44px；支持系统返回与左缘滑动返回。
- 打开 Bottom Sheet 后，系统返回优先关闭 Sheet。
- 深链进入详情时，返回应落到对应列表，而不是空白页。
- Tab 内滚动位置在返回时保留，切 Tab 时重置到顶部。

### 6.3 弹层选择

- **Bottom Sheet**：选择日期、行程、空间、分类、筛选、评论、邀请、导出。
- **Dialog**：删除旅行、退出空间、移出成员、清除预算、取消未保存表单。
- **全屏页**：新建旅程、写回忆、编辑资料等多字段流程。
- **全屏浮层**：图片查看、画册阅读。

### 6.4 表单

- 标签在输入框上方；必填项使用 `*` 或文案说明。
- 输入框聚焦时边框变主色，并显示 3px 浅色 focus ring。
- 失焦校验；提交时再次校验；错误紧贴字段下方。
- 数字输入使用 `inputmode="decimal"`；日期使用移动端日历。
- 键盘弹起时，底部提交按钮上移，不被遮挡。
- 离开未保存表单时弹出确认。
- 提交按钮只允许一个主 CTA；成功后 Toast + 返回上一级或进入详情。

### 6.5 列表与刷新

- 首次加载：骨架屏，保持真实布局高度。
- 下拉刷新：首页、旅程、旅行圈、通知等顶层列表。
- 上拉加载：旅行圈、评论、通知；底部显示“加载中 / 没有更多”。
- 空态：图标 + 标题 + 一句说明 + 一个明确动作。
- 错误态：保留已加载内容，顶部或局部显示错误条 + 重试。
- 乐观更新：点赞、收藏、评论先更新 UI，失败回滚并 Toast。

### 6.6 加载与反馈

- 页面首屏：Skeleton，不用整页转圈。
- 局部操作：按钮内 spinner，按钮文字变为“保存中…”。
- Toast：2 秒自动消失，不遮挡底部操作区。
- 重要结果：Dialog 或页面内结果卡，不只依赖 Toast。
- 离线：顶部黄色提示条；“待同步”徽标 + 同步中心入口。

### 6.7 破坏性操作

- 删除、退出、移出成员必须二次确认。
- 确认文案说明“会发生什么”，而不是只问“确定吗”。
- 破坏性按钮使用 danger 色，且不与主操作并排抢焦点。
- 删除后使用 Toast 说明结果；必要时提供撤销（若业务允许）。

### 6.8 社交互动

- 访客可浏览公开内容；点击互动时统一引导登录。
- 点赞、收藏、评论、分享在卡片与详情页保持一致图标语义。
- 评论使用底部面板；发送后立即出现在列表，失败回滚。
- 关注、屏蔽、举报放在作者主页或详情更多菜单，避免列表误触。
- 屏蔽后立即从 Feed 移除，并提供撤销入口。

### 6.9 离线与同步

- 离线时顶部显示明确提示，不阻断浏览。
- 本地待同步内容使用“待同步”标签。
- 待同步内容禁止编辑时，说明原因并提供“立即同步”。
- 同步中心按内容列出待上传项。
- 同步完成后局部刷新，不整页跳转。

### 6.10 无障碍

- 所有图标按钮必须有 `aria-label`。
- 表单字段必须有 label。
- 文本与背景对比度 ≥ 4.5:1。
- 焦点态可见；弹层打开时锁定背景滚动。
- 不使用颜色作为唯一状态信号，配合图标或文字。

## 7. 移动端尺寸

- 设计基准：375 × 812。
- 兼容范围：360–430px 竖屏。
- 最小触控宽：320px。
- 不做 PC 双栏、不做平板多栏。
- 顶部、底部使用 `env(safe-area-inset-*)`。
- 图片比例：4:3、3:4、1:1、16:10；列表封面统一 4:3。

## 5. 图标与动态资产升级

### 5.1 选型

- **主线性图标：IconPark（Apache-2.0）**  
  来源：https://github.com/bytedance/IconPark  
  选择原因：线条圆润、几何比例统一、48×48 原始网格适合移动端小尺寸显示，且可以内联为单文件 SVG，继续使用 `currentColor` 跟随主题色。
- **3D 动态图标：Microsoft Fluent Emoji 3D（MIT）**  
  来源：https://github.com/microsoft/fluentui-emoji  
  选择原因：成熟的 3D 材质与柔和光影，适合承担低频、高情绪价值的纪念与反馈节点。  
  实现方式：将 3D 原图压缩为 160px WebP 并以 data URI 内嵌，再用 CSS 做轻微浮动与延迟摇动，不依赖 Lottie、React 或额外脚本。
- **花瓣网**：仅作为设计趋势与配色灵感参考，不直接下载、打包其素材。花瓣上的大量图片授权状态不明确，不适合作为可分发 Demo 的资产来源。

### 5.2 使用落点

- 全局导航、按钮、列表、表单：统一使用 IconPark 线性图标。
- 首页「重要日子」：3D 爱心，强调纪念感。
- 新建旅程页头部：3D 飞机，暗示出发。
- 纪念相册上锁页与解锁面板：3D 锁，降低密码流程的紧张感。
- 空状态：3D 指南针 / 相机 / 锁 / 地图，分别对应旅程、相册、私密内容与搜索无结果。
- Toast 反馈：普通反馈使用 3D 星星，成功类反馈使用 3D 礼花。

### 5.3 动效与无障碍

- 默认动效为 3.8s 的轻微上下浮动与 ±2° 摇摆，避免持续大幅运动。
- 每个 3D 图标最多只承担一个视觉焦点，不铺满全站。
- 3D 图标均为装饰元素，使用 `aria-hidden="true"`，不替代按钮文字或业务图标语义。
- 支持 `prefers-reduced-motion: reduce`，系统开启减少动态效果时完全停止动画。
- 原始素材与完整许可证文本见 `THIRD-PARTY-NOTICES.md`。
