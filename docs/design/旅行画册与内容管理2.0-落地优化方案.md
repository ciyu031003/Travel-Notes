# Travel-Notes「内容管理 2.0 + 旅行画册 2.0」落地优化方案

> 结合：`D:\Desktop\Travel-Notes_内容管理与旅行画册2.0_UI重构方案.md`（总纲）
> 前置输入：当前项目代码进展 2026-08-28 实况（含 2026-08-27 移动端交互收官、UI-V3 收敛、旅行圈/相册已落地的部分）。
> 原则：**不改 Prisma schema**；优先复用既有数据模型、既有 travel.* / album.* 设计 token、既有 ui/ 组件、既有媒体变体链；逐 Phase 独立验证、可回滚。

## 0. 结论先行（两条线，均无需改库）

| 线 | 目标 | 关键判据 | 是否改 schema |
|---|---|---|---|
| A. 内容管理 2.0 | 拆分「文章可见性(私密/公开)」×「旅行圈分享(未分享/已分享)」；修复公开/私密不稳定 | 文章可见性 = `Post.isPublic`；旅行圈分享 = `TravelPost` 是否存在 | 否 |
| B. 旅行画册 2.0 | 默认「Travel Book · 旅行摄影杂志」；银河降为可选沉浸模式；图片分级懒加载 | `Travel → TravelDay(章节) → Memory → Media` 现成映射 | 否 |

## 1. 现状与根因分析

### 1.1 内容管理：公开/私密不稳定的根因（已定位）

- `lib/services/post-service.ts:174-176`
  ```ts
  async updatePost(id, input) {
    await this.postRepo.update(id, input)   // 更新 isPublic
    await syncPublicPostToCircle(id).catch(() => {})  // isPublic 一变就自动同步旅行圈
  }
  ```
  `syncPublicPostToCircle`（`lib/modules/social/travel-post.service.ts:137`）在 `post.type==='travel' && published && isPublic` 时建/更新 `TravelPost`，否则删除。后果：**`isPublic` 同时承载「文章公开」与「分享到旅行圈」两个语义**。

- 前端 `app/admin/page.tsx:97-113` 的 `togglePublic`：
  ```ts
  const res = await fetch(...PUT { isPublic: !post.isPublic })
  if (res.ok) setPosts(prev => prev.map(p => p.id===post.id ? {...p, isPublic:!post.isPublic} : p))
  ```
  **乐观更新且不 refetch**。本地只翻 isPublic，与后端真实状态脱节；一旦有其它刷新（或后端在 isPublic=false 时被其它自动逻辑改动）回流，就显示旧值 →「短暂私密后又公开」。

### 1.2 相册：现状与可复用资产

- 入口：`app/album/page.tsx`（客户端）双模式：`space`（银河，`GalaxyAlbumScene`）+ `pixel`（拍立得墙 `PolaroidWall`）。默认 `space`（银河）。
- `GalaxyAlbumScene` / `PolaroidWall` / `TravelStarMap` 已用 `next/dynamic` 做 `ssr:false` 按需拆包 —— Three.js **已 code-split**，问题只是**仍是默认渲染**。
- 数据来源（`/api/album`）：`cities`（travel Post 按城市聚合）+ `albums`（Album 实体）。
- 媒体变体已具备（`lib/infrastructure/media-variants.ts`）：THUMBNAIL(480)/PREVIEW(1600)/BLUR(16)/ORIGINAL。`AlbumMediaItem` 已暴露 `thumbnailUrl / previewUrl`。
- 设计 token：`travel.*` 暖陶土 `#A85F3A`、`travel-cream` 米白；`album.*` 深色银河系（Travel Book 应改用 travel.* 暖白系）。
- `ui/` 组件：Modal / Select / Button / Card / Badge，可复用。

## 2. 设计决策（需你确认）

### 决策 A1：文章可见性 × 旅行圈分享彻底解耦（不改库）
- `Post.isPublic` = **文章本身是否公开**（公开则个人文章页所有登录用户可见）。
- `TravelPost` 是否存在 = **是否分享到旅行圈**（分享的公开副本，独立于文章可见性）。
- 效果：一篇文章可保持**私密**但**已分享到旅行圈**（符合总纲 3.2）。
- 行为影响（需确认）：`updatePost/createPost` **不再**在 isPublic 变化时自动 `syncPublicPostToCircle`；改为显式「分享/取消分享」动作驱动。存量已 `isPublic=true` 且已有 TravelPost 的帖子，其 TravelPost 保留不变。

### 决策 A2：分享动作需要的最小入参（第一版）
- 「分享到旅行圈」只需：所属标题(title 取文章)、摘要(summary 取文章)、分享范围（`PUBLIC`/`SPACE`，默认 PUBLIC）、可选所属旅行(travelId，TravelPost 已有该字段)。
- 第一版不做封面选择/自定义分享文案（可作后续 Phase）；避免扩 schema。

### 决策 B1：Travel Book 的「章节」来源
- 以 `Travel` 模型为准：**一个 TravelDay = 一个 Chapter**（章节标题=TravelDay.title，缺失则 `Day 01`）。
- 数据按 `Travel` 组织（含 travelId、cover、startDate、days→memories→media），**不用**当前 Post 按城市聚合的 `cities` 来驱动画册（那套更接近「照片墙」）。
- 若 `Travel` 数据为空，再回退到 `albums`（Album 实体）作为「仅照片」画册。

### 决策 B2：视觉体系复用现有 travel.* 暖白 token，不新造色板
- 背景 `travel-cream`、纸张近白、正文墨黑、强调陶土 `#A85F3A`。与总纲「暖白+墨黑+暖灰+陶土」吻合。

## 3. 具体改动方案（逐 Phase，独立验证）

### Phase 0 —— 稳定性修复（P0，先做，最小改动）
**目标：公开/私密状态三端一致（数据库=API=前端）。**

- `lib/services/post-service.ts`：`updatePost` 内 `isPublic` 变化时**不再**自动 `syncPublicPostToCircle`，改为仅在存在显式分享动作时调用（见 Phase 1）。`createPost` 同理拆分。
- `app/admin/page.tsx` `togglePublic`：
  1. 请求前置 loading（`togglingId` 已存在，接入禁用态）。`togglingId===post.id` 时禁用该按钮/加 spinner。
  2. 改为**服务端成功后 refetch**（`await fetchPosts()`），不做仅本地翻转；失败时**回滚**。
  3. 用 `useMutation` 或本地 `finally` 逻辑保证 UI 与服务器一致。
- 新增/确认接口契约：`PUT /api/admin/posts/:id` 返回更新后的 `post`（`ok({ post })`），前端用返回对象覆盖本地，而非 `!post.isPublic` 反转。

**验收**：点击「私密」→ loading → 服务器更新 → 返回最新 → UI 更新 → 刷新页面仍是私密。

### Phase 1 —— 内容管理 2.0：文章卡片分享态（P1）
**目标：卡片直接管理「分享到旅行圈」，无需进编辑页。**

- `app/admin/page.tsx` 文章卡片底部区域重排（参考总纲 4.1）：
  ```
  🟢 已发布   🔒 私密/🌐 公开        (文章自身可见性)
  🌍 已分享到旅行圈 / 未分享         (旅行圈分享态)
  ↗ 分享/管理分享  ✎ 编辑  🗑 删除
  ```
- `Post` 列表项补充 `circleShared:boolean`（=该 postId 是否存在 `TravelPost`）。由 `post-service` 的列表查询附带（一次 `findMany` 查 `TravelPost` postId in (...)）。
- 新增分享入口交互：点击「🌍 分享到旅行圈」弹出轻量 Dialog / Bottom Sheet（`ui/Modal`），含：
  - 标题/摘要预览（只读）
  - 所属旅行（可选，下拉 `ui/Select` 列出已存在 Travel）
  - 分享范围（`● 公开  ○ 仅空间成员`）
  - `[取消] [分享到旅行圈]`
- 服务端：新增/复用接口
  - `POST /api/admin/posts/:id/share` → `sharePostToCircle(id, { travelId?, visibility })`（写入 `TravelPost`，要求 `published=true`）
  - `DELETE /api/admin/posts/:id/share` → 取消分享（删除 `TravelPost`）
  - `lib/modules/social/travel-post.service.ts` 新增 `sharePostToCircle` / `unsharePost`；**保留** `syncPublicPostToCircle` 仅供无显式动作的旧路径兼容，但不再由 isPublic 触发。
- 分享后卡片态更新（refetch）。

**验收**：私密文章也可分享到圈；旅行圈 Feed 出现该帖；取消分享后移除。

### Phase 2 —— 旅行画册基础版：Travel Book（P2）
**目标：默认模式从「银河」切到「旅行画册」，可浏览跟读故事。**

- 新增数据端点：`GET /api/travel-book`（或扩展 `/api/travels`），返回每本画册：
  ```
  { travelId, title, slug, cover(large), startDate, endDate,
    travelType, companions,  // 复用旅行关系徽标
    chapters: [ { dayIndex, title, date, summary,
                  memories: [ { content, mood, location,
                                media: [ {thumbnailUrl, previewUrl, width,height} ] } ] } ] }
  ```
  复用 `lib/modules/travel/travel.service.ts` 的 gather + `media.variants`（THUMBNAIL 列表、PREVIEW 画册页、ORIGINAL 点开大图）。
- 新增组件目录 `components/album/travel-book/`（总纲 22，按实际结构调整）：
  - `TravelBook.tsx`（壳）+ `TravelBookNavigator`(左/右、章节跳转、页码 01/08) + `TravelBookProgress`
  - `templates/`：`HeroPage / SplitPage / PhotoGridPage / FullBleedPage / QuotePage / FilmStripPage / MapPage / ChapterIntroPage`
  - 页面模板按「章节内容」自动编排：每个 memory 优先 `Hero`/`FullBleed`，同章多图用 `PhotoGrid`，含文字+单图用 `Split`，地点/路线用 `MapPage`（复用 `components/china-map` 或 `TravelTimeline` 能力）。
- `app/album/page.tsx`：把默认 `viewMode` 从 `space` 改为 `travel-book`；三种展示模式切换：`📖 旅行画册(默认) ▦ 照片网格 ✨ 银河空间`。银河/拍立得保留为可选。
- 封面：首屏仅加载封面大图（`cover` 用 PREVIEW），标题/日期/地点克制成杂志感；封面比例 + 微弱阴影，不打 3D 书架。

**验收**：进入相册默认看到「我的旅行画册」列表 → 点开一本 → Cover → 章节 → 左右翻页；桌面/移动端均正常。

### Phase 3 —— 视觉升级（P3）
- 画册内统一 `travel.*` 暖白系（背景 travel-cream、图文墨黑、强调陶土）；低圆角（图片 2-6px、纸张 0-4px、按钮 8px，封面 0）。
- 标题用 Serif（优先已有字体/系统字体，不引入大包）：中文 Noto Serif SC / 思源宋体，正文 Noto Sans SC。
- 轻微纸张质感（克制）：微弱阴影 + 极轻 noise，禁撕纸/胶带/贴纸/满屏手写。
- QuotePage / FilmStripPage / MapPage / 旅行总结页（统计：天数/城市/照片/路线）。
- 翻页动画：`transform+opacity+轻微 scale`，300-400ms，`prefers-reduced-motion` 降级为淡入直切。

### Phase 4 —— 图片性能（P4）
- 图片分级取用：列表/封面 `THUMBNAIL`；画册页 `PREVIEW`；查看大图 `ORIGINAL`。
- 当前页立即加载、下一页预加载、更远页不加载；禁用「一次拉 100 张原图」。
- 所有图片给定宽高比：`aspect-ratio` + `object-fit` + 占位（BLUR 变体做 blur placeholder / 轻 skeleton），避免加载后 CLS。
- 可选：WebP/AVIF、CDN/对象存储、按需分包。

### Phase 5 —— 银河降级为可选（P5）
- `GalaxyAlbumScene` 与全部银河代码保持现状，但仅当用户**显式选择**「✨ 银河空间」时才渲染——默认路径不加载（已 code-split，确保默认不打包）。
- 保持 `components/album/space/*` 独立，Travel Book 不 import 它。

## 4. 需要你拍板的点

1. **A1 行为变更**：`isPublic` 不再自动触发分享到旅行圈；改为文章卡片上显式「分享」按钮。存量已分享帖子保留。是否接受？
2. **B2 数据源**：Travel Book 以 `Travel` 模型（TravelDay=章节）驱动，而非当前 Post 按城市聚合。当某次旅行无 Travel 数据时回退专辑(仅照片)。是否接受？
3. **Phase 拆分顺序**：建议先做 Phase 0+1（内容管理，改动小、见效快），再做 Phase 2-5（画册，改动大）。是否按此顺序推进？

## 5. 不破坏的边界

- 不改 `prisma/schema.prisma`（除非 Phase 后续确需某个字段，届时先停并说明）。
- 不绕过 Service Layer / 权限校验（Space 成员、RBAC、`lib/modules/access`）。
- 保留：Galaxy、拍立得、星图、留言、上传/删除/查看图片、导出、Admin。
- 每 Phase 结束跑：`tsc` / `npm run build` / `npm run lint` / 相关测试，回归首页、travel、album、circle、map、admin、深浅色。
- 服务器非 git 仓库：改动后用 scp 增量同步 + `docker compose up -d --build app` 部署（勿用 tar 管道，曾踩坑）。
