# 旅行圈 · 快捷点赞

> 日期：2026-09-24 · 状态：**已实施**
> 触发需求：「旅行圈浏览别人的旅行记录的时候，加入快捷点赞」

---

## 1. 改之前是什么样

旅行圈的卡片（`SocialFilmCard`）上，点赞数是一个**只读的 `<span>`**：

```tsx
// 改前
<span className="inline-flex items-center gap-1 text-xs tabular-nums">
  <Icon icon={Heart} size="sm" />{stats.likes}
</span>
```

想点赞必须点开卡片 → 进 `/circle/[postId]` 详情页 → 用 `SocialBar` 点赞。
浏览别人的旅行记录时，每一次点赞都多一跳。

而且卡片根元素在 `onOpen` 存在时是 `<button>`（`const Tag = onOpen ? 'button' : 'div'`），
**往里塞任何互动控件都会变成 `<button>` 嵌套 `<button>`** —— 非法 HTML，点击语义也会错乱。
这是"卡片上放不了点赞按钮"的根本原因，必须先修结构。

## 2. 数据链路（已有，无需改后端）

快捷点赞**完全复用**现有的圈子点赞体系，没有新增接口、没有改表：

| 环节 | 位置 |
|---|---|
| 读：列表带 `isLiked` / `likeCount` | `lib/modules/social/social.service.ts` `attachViewerState()`（feed 三个 tab、用户主页、我的收藏都走它） |
| 写：`POST`/`DELETE /api/social/posts/[id]/like` | `app/api/social/posts/[id]/like/route.ts` → `togglePostLike()`（改 `TravelPost.likeCount` 计数 + `PostLike` 关联） |
| 写封装（含离线队列） | `lib/modules/offline/social-write.ts` `toggleLike(postId, liked)`；原生壳乐观写本地 + 入队，Web 直连接口 |

> 注意：圈子点赞与通用的 `/api/likes`（`Like` 表、`targetType: post|moment`、基于 `visitorId`）
> 是**两套独立体系**。快捷点赞走的是圈子这一套（需要登录）。

## 3. 改了什么

### 3.1 新增 `components/social/QuickLike.tsx`

浮动胶囊按钮（参考 Uiverse「Buttons」分类的浮动胶囊 + 按压回弹，按本项目规范重写为触屏可用）：

- 触达 **≥44px**（实测 54.6×44）
- 按压 `m-pressable`；点赞时心形播放一次 `.m-pop` 弹跳
- **乐观更新 + 失败回滚**；原生壳走离线队列
- 状态自持（与 `SocialBar` 同模式），父组件不需要维护点赞状态
- 两种外观：`on-media`（压在照片上，`bg-black/45` + `ring-white/25` 保证可读）／`on-surface`
- **未登录**：`loginHref` 传入后点击引导登录，不产生无效请求（与旅行圈"访客可看、互动需登录"规则一致）

### 3.2 `SocialFilmCard` 结构调整

| 改动 | 原因 |
|---|---|
| 根元素固定为 `<div>`，另铺一层绝对定位的 `<button>` 作「打开详情」点击/键盘层（`z-[1]`） | 修掉 `<button>` 嵌套；互动控件以 `z-[2]` 叠在其上 |
| 封面右下角浮动快捷点赞（card 变体）；hero 变体放在底部信息行 | 不必进详情页即可点赞 |
| **从 stats 行移除只读 ♡ 数字**（保留 💬 🔖） | 点赞已可交互，避免同一个数字出现两次 |
| hero 遮罩上的文字改**固定浅色** | 见下方 3.3 |

### 3.3 ⚠️ 顺带修掉的对比度 bug

hero 变体的文字永远压在 `from-[#050505]/90` 的深色遮罩上，但原先用的是**主题 token**：

```
实测（浅色主题）：hero 标题 color = rgb(43, 33, 27)   ← --social-text
                 遮罩 ≈ 90% 黑 → 近黑字压近黑底，几乎不可读
```

同样受影响的还有作者名、💬/🔖 计数、城市名（`--social-accent` 浅色下是深棕）。
已改为固定浅色：标题 `text-white`、作者 `text-white/80`、计数 `text-white/75`、城市 `text-travel-bloom`。
暗色主题下 `--social-text` 本就是浅色，因此**暗色几乎无变化，浅色主题得到修复**。

> 规律：**压在深色遮罩/照片上的文字不能用主题 token**，必须用固定浅色；否则一换主题就失效。

## 4. 覆盖范围

`SocialFilmCard` 的三个使用点全部接上（都从同一套 `attachViewerState` 拿到 `isLiked`）：

| 页面 | 组件 | 说明 |
|---|---|---|
| `/circle` 旅行圈 | `TravelCircleFeed` | **本次需求主体**；访客态传 `loginHref` |
| `/circle/user/[id]` 别人的主页 | `UserProfile` | 浏览某人的旅行记录 |
| `/me/favorites` 我的收藏 | `FavoritesGrid` | 一致体验 |

## 5. 关于参考组件里那 5 个表情（未采用）

用户给的原型是 5 个表情反应（👍 Like / 👏 Cheer / 🎉 Celebrate / ✨ Appreciate / 🙂 Smile）。
**本次只做了单一 ♡**，因为多表情反应需要：

1. `PostLike` 加 `kind` 列，唯一约束从 `[postId, userId]` 改为 `[postId, userId, kind]` —— **要迁移生产库**；
2. `TravelPost.likeCount` 这个反范式计数要扩成按表情分组（或读时 groupBy）；
3. 接口 `like` 收 `kind` 参数；通知文案"赞了你的旅行"要按表情分化；
4. 与产品既定规则冲突 —— `docs/design/UI-V3-全面优化方案.md` §三.7「互动克制原则：只保留 ♡ / 💬 / 收藏三项」。

另外原型里的交互是 `hover:` + tooltip，**触屏无效**；本项目改为按压反馈。

若确实要上多表情，卡片结构、乐观更新、离线队列这些环节都已就绪，增量只剩"迁移 + 聚合 + 接口"。
