## 一、M1（第一阶段）实施范围

> 只做两件事，全部是"记忆闭环"主线的既有数据模型收敛，不新增表、不破坏性迁移。

### M1-A1：Album 绑定 Travel（相册=一次旅行）

**目标**：消灭"后台纪念相册（Album 实体）与前台城市相册（Post 聚合）数据模型割裂"的根因。

**改动**：
1. `prisma/schema.prisma`：`Album` 增加可选 `travelId Int?` + 关系 `travel Travel?`（onDelete: SetNull）。
2. `scripts/apply-schema-migration.cjs`：幂等加列（`ALTER TABLE Album ADD COLUMN IF NOT EXISTS travelId INT NULL` + 索引）。
3. `lib/modules/album/album.service.ts`：`AlbumItem` 增 `travelId`；mapAlbum 带出；`createAlbum`/`updateAlbum` 支持 `travelId`。
4. `app/api/admin/albums/route.ts`（POST）+ `[id]/route.ts`（PUT）：body 透传 `travelId`。
5. **离线层同步**：`lib/modules/offline/schema.ts` 本地 album 表加 `travelId` 列（幂等建表 v3）；`pull-dispatcher.ts` pullAlbums 映射 `travelId`。
6. 后台 `app/admin/albums/page.tsx`：创建/编辑相册时可选关联旅行（下拉）。
7. 前台 `/album`：`/api/album` 返回的 albums 带 `travelId`（供后续按旅行筛选，本期仅透出）。

**DoD**：后台可为相册绑定一次旅行；`/api/admin/albums` 与 `/api/album` 均返回 travelId；本地 SQLite album 表含 travelId；无破坏性迁移。

### M1-A4：旅行详情按天叙事时间线

**目标**：把"一条旅行 → 每一天 → 地点 → 照片 → 回忆"串成可滚动的时间线叙事（天=章节）。

**改动**：
1. `lib/modules/travel/travel.service.ts`：`getTravelDetail` 已返回 days（含 itinerary/日期/标题/摘要），补充按天聚合照片与回忆：
   - 每 day 附 `memories`（travelDayId 匹配的 Memory）与 `media`（经 memory 或 travelId 关联的照片，首期用 travelId 关联的 Media + memory 的照片）。
2. 新增 API：`GET /api/travels/[id]/timeline` → `{ days: [{ date, title, summary, memories, photos, itinerary }] }`（按 sortOrder 升序）。
3. `app/travel/[slug]/TravelDetailShell.tsx`：内容区下方新增「按天时间线」区块（加载 timeline API），垂直时间线 + 日期章节 + 照片缩略 + 回忆卡片 + 行程项；`prefers-reduced-motion` 下静态渲染。
4. 与地图联动（本期轻量）：照片/回忆带 location 时显示地标名，地图深链留待 A5。

**DoD**：典型旅行的详情页能按天看到"日期 → 行程 → 照片 → 回忆"；无数据时优雅降级（隐藏时间线区块）。
