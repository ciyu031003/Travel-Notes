# Travel-Notes 多元旅行场景优化设计方案（家庭/朋友/闺蜜/独旅）

> 版本 v1.0 · 2026-08-25 · 基于当前 HEAD `b1dc87c` 数据模型与功能现状
> 背景：产品定位已从「情侣共同旅行」升级为「个人旅行记忆空间」（支持独旅/情侣/朋友/家庭/闺蜜/多人/长期记录），但**数据模型与部分功能仍残留"情侣"语义**，需要系统性去情侣化 + 为多元场景补能力。
> 原则：不推倒重写；在现有 Space/Travel/Memory/Album 模型上做增量；只动前端与数据模型增量迁移，不破坏现有数据。

---

## 一、现状差距分析（基于真实代码）

### 1.1 数据模型残留的"情侣"语义

| 位置 | 现状 | 问题 |
|---|---|---|
| `prisma/schema.prisma` `Visibility` 枚举 | `PRIVATE / COUPLE / PUBLIC` | `COUPLE` 是情侣专属,多元场景下无语义 |
| `Travel.visibility` 默认值 | `@default(COUPLE)` | 新建旅行默认"情侣可见",与新定位冲突 |
| `Travel` 模型 | 有 `spaceId/ownerId`,**无同行者、无旅行类型** | 无法表达"和谁一起去的"(家人/朋友/闺蜜/独旅) |
| `Space` 模型 | 有 OWNER/MEMBER/VIEWER 角色,但**无空间类型** | 无法区分"家庭空间/朋友空间/闺蜜空间" |
| 前端文案 | 后台仍见"情侣"残留(如 admin/travels 创建提示) | 与新定位不一致 |

### 1.2 功能维度差距

| 场景能力 | 现状 | 多元场景需要 |
|---|---|---|
| **同行者** | 无字段/无录入 | 每次旅行标注同行者(家人/朋友/闺蜜/独旅),并聚合"和谁去过哪" |
| **旅行类型** | 无 | 独旅/情侣/家庭/朋友/闺蜜 标签,影响相册分组与统计 |
| **空间关系** | 一个 Space 多人 | 可创建"家庭空间/朋友空间"并区分关系类型 |
| **相册归属** | 相册关联 travel/space/user | 需要"按同行者/旅行类型"组织相册 |
| **统计** | 省份/次数/照片 | 需要"和谁去了 N 次 / 家庭旅行次数"等维度 |
| **邀请** | 邮箱/账号邀请进 Space | 需要按关系类型邀请(家人/朋友),角色仍 OWNER/MEMBER |

## 二、设计方案

### 2.1 数据模型增量（最小侵入）

#### ① `Travel` 增加「旅行类型 + 同行者」

```prisma
model Travel {
  // ...现有字段
  travelType   TravelType  @default(ALONE)   // 独旅/情侣/家庭/朋友/闺蜜/其他
  companions   Json?       @db.Json          // 同行者列表 [{name, relation}] 或 [{userId, relation}]
}
```

```prisma
enum TravelType {
  ALONE      // 独旅
  COUPLE     // 情侣
  FAMILY     // 家庭
  FRIENDS    // 朋友
  BFF        // 闺蜜/兄弟
  GROUP      // 多人结伴
  OTHER
}
```

> 设计要点：
> - `companions` 用 Json 存 `[{ name, relation, userId? }]`：**轻量、不建表**、兼容"未注册用户"(家人不一定有账号)；有 userId 时可在档案页聚合"和 X 一起去过 N 次"。
> - `travelType` 是枚举,前台筛选/统计/相册分组都靠它。

#### ② `Visibility` 去情侣化 + 补「成员级」

```prisma
enum Visibility {
  PRIVATE    // 仅自己
  SPACE      // 空间成员可见（替代 COUPLE）
  PUBLIC     // 公开
}
```

> 把 `COUPLE` 改为 `SPACE`(语义:空间成员可见)。`Travel.visibility` 默认值同步改为 `SPACE`。这是一次迁移：`UPDATE Travel SET visibility='SPACE' WHERE visibility='COUPLE'`(枚举值重命名,数据无损)。

#### ③ `Space` 增加「空间类型」

```prisma
model Space {
  // ...现有字段
  spaceType  SpaceType @default(COUPLE)
}
enum SpaceType {
  COUPLE     // 情侣/双人空间
  FAMILY     // 家庭空间
  FRIENDS    // 朋友/闺蜜空间
  SOLO       // 个人空间
  OTHER
}
```

> 空间类型用于 UI 呈现(图标/命名/入口分组),不影响权限(OWNER/MEMBER/VIEWER 保持不变)。

### 2.2 功能设计

#### ① 旅行录入：同行者 + 类型（低成本高价值）

- **新建/编辑旅行**时增加两个字段：
  - 旅行类型（单选胶囊:独旅/情侣/家庭/朋友/闺蜜/结伴）
  - 同行者（可多选:从空间成员选,或自由输入姓名+关系）
- **旅行详情页**显示「类型徽章 + 同行者头像/名字」,替代旧的"情侣向"呈现。
- **首页/时间线**按类型给条目加视觉标识（如家庭=绿色系、朋友=蓝系、独旅=灰,全部用克制暖调,不用花哨）。

#### ② 档案页（/me）：新增「同行维度」

- 核心统计扩展：「和谁去过」——按 relation 聚合 `家庭旅行 N 次 / 朋友旅行 N 次 / 独旅 N 次`
- 「我的旅行」列表加类型筛选胶囊（全部/独旅/情侣/家庭/朋友）

#### ③ 相册管理（重点优化）

现状：相册关联 `travel/space/user`,浏览维度单一（按城市/按旅行）。

**优化方向（克制、不推翻）**：

| 维度 | 做法 |
|---|---|
| **按旅行类型分组** | 相册页顶部加类型 Tab（全部/家庭/朋友/独旅…）,相册按 `travel.travelType` 分组 |
| **按同行者筛选** | 点某位同行者头像 → 只看"和 TA 一起的照片"（基于 `Memory.companionIds` 或 travel.companions） |
| **封面与命名** | 相册卡片显示类型徽章;命名建议带类型（如「2026 家庭 · 大理」） |
| **独旅支持** | 相册对独旅不做"双人"假设;`AlbumUnlockModal` 的"纪念日解锁"改为**可选**（独旅用户无纪念日也可解锁） |

#### ④ 统计看板（/dashboard）：加同行维度

- 「内容构成」或新增一块：「旅行类型分布」（家庭 N / 朋友 N / 独旅 N,轻量条形）
- 省份卡增加"和谁"的副信息（可选,克制）

### 2.3 前端去情侣化残留（必做）

| 位置 | 现状 | 改 |
|---|---|---|
| `Visibility` 相关 UI | 若有 COUPLE 字样 | 改 SPACE/成员可见 |
| 后台创建旅行提示 | 检查是否有"情侣"文案 | 改中性 |
| `AlbumUnlockModal` | "输入纪念日解锁" | 增加"无纪念日?直接解锁"选项 |
| `AnniversarySection` | 情侣纪念日 | 改"重要日子"（保留功能,去情侣文案） |

## 三、实施优先级

### P0（必做 · 去情侣语义,低成本）
1. `Visibility.COUPLE → SPACE` 枚举迁移 + 默认值改
2. `Travel.travelType` + `companions` 字段 + 录入 UI
3. 前端 `COUPLE` 文案残留清理

### P1（高价值 · 多元场景体验）
4. 档案/时间线/首页 按旅行类型筛选与标识
5. 相册按类型 + 同行者组织（Tab + 筛选）
6. `AlbumUnlockModal` 支持无纪念日解锁

### P2（增强 · 可选）
7. `Space.spaceType` + 空间创建时选类型
8. 统计看板加"同行维度"分布
9. 同行者聚合："和 X 去过 N 次"（档案页）

### P3（远期 · 不急着做）
10. 邀请流程按关系类型分组
11. 同行者驱动的智能时间线（"和家人的旅行回忆"专题页）

## 四、验证方式

- 每步 `prisma migrate`(增量,不破坏数据)+ `tsc` + `next build`
- 用现有旅行数据验证：老数据 `visibility=COUPLE` 迁移为 `SPACE` 后,登录态可见性不回归
- 相册/档案/统计截图 QA(视觉检查)

---

## 五、一句话总结

**核心不是加功能,而是"让数据能表达'和谁、什么类型'的旅行"**——加 `travelType + companions` 两个字段,驱动相册分组、档案统计、筛选标识,同时把 `COUPLE` 残留清成 `SPACE`,让系统天然适配独旅/家庭/朋友/闺蜜,而不是只换文案。
