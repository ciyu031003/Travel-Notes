# 旅行模块重构方案（规划 / 上传 / 修改入口 + 新建旅行参考圆周旅迹）

> 触发：真机反馈三条
> 1. **缺乏规划入口**：每天干什么、花销预计多少、行程怎么样，都没有入口；
> 2. **缺乏上传入口**：旅行完想传图片，找不到入口；
> 3. **缺乏修改入口**：新建完旅行后没有后续动作可添加/修改，而且「新建旅行」本身也找不到在哪；
> 4. 新建旅行页面按圆周旅迹的 UI / 色彩 / 功能做**全面重构**。
>
> 本文档 = 代码级现状审计 + 根因定位 + 参考产品拆解 + 分期实施方案 + 验收标准。
> **本文档只做方案，不改代码**；确认后再按 §5 落地。
>
> 上一版方案：`docs/design/新建旅行重构方案-参考圆周旅迹.md`（v1.10.0，阶段 1/2 已上线）。
> 本次不是推翻它，而是补它**漏掉的三件事**：入口可见性、建完的落地、详情页被全屏相册吞掉。

---

## 0. 一页结论（TL;DR）

| 你的抱怨 | 真正的原因（不是"功能没做"，而是"做了但到不了"） |
|---|---|
| 找不到「新建旅行」 | 移动端**唯一**入口是底部 Dock 中央那个**只有图标、没有文字**的 `+`（`MobileBottomNav.tsx:64-73`）。列表页右上角原来的「新建旅行」按钮在 commit `96ed895` 被**主动删除**（"统一由 Dock 加号入口"）。有旅行之后，列表空态里那个「记录第一次旅行」按钮也不再出现。 |
| 新建完没有后续动作 | `app/travel/new/page.tsx:20` 硬编码跳 `/travel/<slug>`，**没走** `travelDetailHref()`。而本地壳（APK）静态导出目录 `www/travel/` 里只有 `new / detail / record / placeholder` 四个 HTML，**没有** `/travel/<slug>`。→ 点「开始记录」后落在导出里不存在的路由。 |
| 有了照片后什么都点不到 | 详情页只要**有任何一张图片**就渲染 `TravelDetailClient`，它是 `fixed inset-0 bg-black z-50` 的**全屏不透明相册、没有关闭按钮**（`TravelDetailShell.tsx:153` + `TravelDetailClient.tsx:239`）。于是同一页里的「记录今日 / 编辑信息 / 按天时间线（记一笔、添加行程）」全部被盖在 z-50 之下，**物理上不可达**。这是"规划/上传/修改三个入口都找不到"的**平台级总根因**。 |
| 规划 & 花销没有入口 | 行程编排（`TravelDay`/`ItineraryItem` + `TravelTimeline` + `ItineraryEditor`）**已经做完了**，只是埋在详情页最底部、且被上面的全屏相册盖住；而**花销/预算前台一行代码都没有**——`Expense` 模型和 `addExpense` 已存在，但接口只挂在 `/api/admin/**` 且要求 `canManageContent` 能力，普通用户在 App 里用不了，且**没有预算字段**。 |
| 上传找不到 | 「记一笔」抽屉（`MemoryComposer`）里**能**传照片（走 `POST /api/memories/:id/photos`），但入口同样被全屏相册盖住；而「记录今日」旧页（`TravelRecordPage.tsx`）**完全不收照片**，两套入口能力不一致。另外**没有**"把这批照片传到这本旅行（不挂某条回忆）"的批量入口。 |

**一句话**：功能存量比你以为的多得多（行程、回忆、照片、编辑信息都有接口和组件），
真正坏掉的是**入口、跳转、和详情页的信息架构**。本次重构 = 先把三个入口接回来（P0），
再把详情页从"一个全屏相册"改成"可规划、可上传、可修改的目的地"（P1），
最后补花销预算与偏好问卷（P2）。

## 1. 根因逐条定位（代码级证据）

### R1 · 「新建旅行」的可见入口被删掉了

| 位置 | 事实 |
|---|---|
| `components/layout/MobileBottomNav.tsx:64-73` | 中央 FAB 只有 `<Icon icon={Plus} />`，无可见文字，`aria-label="记录旅行"`。5 个 tab 位里它是第 3 个，和「旅行」tab 没有任何视觉关联 |
| `app/travel/TravelMobileClient.tsx:119` | 注释原文：「新建旅行统一走底部 Dock 栏「+」入口」——页头**没有**任何新建按钮 |
| `app/travel/TravelMobileClient.tsx:166-177` | 「记录第一次旅行」按钮只在 `posts.length === 0` 空态渲染。**有旅行后彻底消失** |
| git `96ed895` | 提交信息：「删除旅行地图页右上角「新建旅行」按钮（统一由 Dock 加号入口）」——入口是**被主动移除**的 |
| `components/layout/MobileBottomNav.tsx:38-51` | FAB 点击先 fetch `/api/check-auth`，未登录跳登录页。**没有任何文字提示"+"=新建旅行** |

结论：入口**存在但不可发现**。用户不会知道那个 + 是"新建旅行"。

### R2 · 建完之后的跳转在本地壳里是死路

| 位置 | 事实 |
|---|---|
| `app/travel/new/page.tsx:19-21` | `router.replace(slug ? `/travel/${encodeURIComponent(slug)}` : '/travel')` ——**全项目唯一**没有用 `travelDetailHref()` 的调用点（其余 6 处都用，见 `grep travelDetailHref`） |
| `lib/routes.ts:13-25` | 明确写死规则：本地壳（`NEXT_PUBLIC_APP_PLATFORM === 'mobile'`）**必须**用 `/travel/detail?slug=...`，因为 `/travel/[slug]` 在静态导出里取不到文件，WebView 会回落 |
| 实测 `www/travel/` 目录 | 只有 `detail.html / new.html / record.html / placeholder.html`（+`placeholder/record.html`）。**没有** `/travel/<slug>.html` |
| `lib/modules/offline/travel-write.ts:40-77` | 原生壳**永远**走本地分支（不判断在线）：写 SQLite + 入 SyncQueue，返回**本地 slug**，从不调 `/api/admin/travels` |
| `app/travel/[slug]/TravelDetailShell.tsx:78-87` | 详情页**只** `fetch('/api/travels/by-slug/:slug/detail')`，**没有** `readWithFallback` 本地兜底（对比 `TravelRecordPage.tsx:43-54` 是有的） |

结论：APK 里「开始记录」→ 跳一个导出里不存在的路由；
即使路由侥幸命中，新建的旅行还在同步队列里、服务端不认识它 → 详情接口 404 → 用户看到「旅行不存在」。
**"建完就没下文"是这两条叠加的结果。**

### R3 · 详情页被全屏相册吞掉（最严重）

| 位置 | 事实 |
|---|---|
| `TravelDetailShell.tsx:153` | `{(images.length > 0 \|\| videos.length > 0) && <TravelDetailClient {...imageProps} />}` |
| `TravelDetailClient.tsx:239` | 根节点 `<div className="fixed inset-0 bg-black z-50">` —— 不透明、全屏、**没有关闭按钮** |
| `TravelDetailClient.tsx:270-272` | 内部滚动容器只装 `mediaItems`（照片/视频） |
| `TravelDetailClient.tsx:419-424` | 最后一张之后只有一行**不可点击**的「继续阅读文章 + ⌄」文案 |
| `TravelDetailShell.tsx:155-177` | 「记录今日」「编辑信息」按钮 → 被盖住 |
| `TravelDetailShell.tsx:245-259` | 空态引导 → 被盖住 |
| `TravelDetailShell.tsx:262-266` | `<TravelTimeline>`（记一笔 / 添加行程 / 照片墙）→ 被盖住 |
| `app/api/travels/by-slug/[slug]/detail/route.ts:43-49` | `images` = 封面 + 回忆照片 + 旧文章图。**只要给旅行传过 1 张照片，详情页就永久变成全屏相册** |

结论：**旅行一旦有照片，这一页就只剩"看图"**。规划、上传、修改三个入口不是没做，是被盖住了。

### R4 · 花销/预算：前台零实现

| 位置 | 事实 |
|---|---|
| `prisma/schema.prisma:700-715` | `Expense`（amount / currency / category / payer / note / happenedAt）已存在 |
| `lib/modules/travel/travel.service.ts:769-792, 833-838` | `addExpense / deleteExpense / findTravelIdByExpenseId` 已存在 |
| `app/api/admin/travels/[id]/expenses/route.ts:11` | 要求 `requireCapability(userId, 'canManageContent')` → **普通用户前台调用会被 403** |
| `app/api/travels/` 实测目录 | **没有** `expenses` 路由；只有 routes / by-slug / [id] / [id]/days / [id]/itinerary / [id]/memories / [id]/timeline |
| `prisma/schema.prisma:410-446` | `Travel` **没有** `budget` 字段 → 「花销**预计**是多少」无处存 |
| `app/admin/travels/page.tsx:493-540` | 记账 UI 只在后台 |

### R5 · 其他影响体验的缺口（顺带记录）

| # | 事实 | 影响 |
|---|---|---|
| a | `app/api/travels/[id]/itinerary/route.ts` **只有 POST**，无 `itemId` 的 PATCH/DELETE | 行程项加错了**删不掉、改不了** |
| b | 无「编辑某天（名称/摘要/日期）」前台接口 | 只能加天，不能改天 |
| c | `TravelRecordPage.tsx` 整页无照片相关代码 | 「记录今日」与「记一笔」两套入口，能力不一致 |
| d | `TravelMobileClient.tsx:180-228` 海报流未渲染 `localOnly` 标记（合并逻辑 `travel-read.ts:101-124` 已带字段） | 待同步的旅行看起来和已同步的一样，用户不知道"还没传上去" |
| e | 详情页仍用 `container-custom` + `text-3xl` 桌面栅格，只有一条 `md:hidden` 返回栏 | 移动端观感与列表页的 `--m-*` 设计系统不一致 |
| f | `TravelDetailShell.tsx:41` `canEdit = userId === ownerId`，`travel-write.ts:70` 本地写 `ownerId: null` | 同步前：详情页 404（R2）；同步后：`app/api/admin/travels/route.ts:72` 会写 `ownerId`，所以最终可编辑。**中间态无兜底** |

## 3. 参考产品拆解（7 张截图 → 可迁移模式）

> 原则不变（沿用上一版 §0）：**只迁移交互模式**，视觉仍走我们自己的 `--m-*` 暖陶土 token
> （`app/mobile.css`：`--m-accent: #C67A4E` / `--m-bg: #FFFBF7` / 卡片圆角 20px）。
> 不抄它的 `#4DA6FF` 蓝、不抄地图当首屏底、不抄 AI 对话式新建。

### S1 · 偏好问卷（截图 1/5、3/5、4/5、5/5）

| 它做了什么 | 可迁移到什么 | 我们的落法（P2） |
|---|---|---|
| 5 步轻问卷：**同行者**（独自/和伴侣/和朋友/一家人，滑杆式单选）→ **惊喜偏好**（多选有机色块）→ **扫兴点**（多选，选中的划红线）→ **特别注意**（避免剧烈运动/晕车/带小孩/带宠物/无障碍/高反） | 新建旅行时收集"这趟想怎么玩"，用于后续行程与推荐 | 把它做成**新建向导的 2-3 步可选问卷**（可跳过）。`TravelType`/`companions` 已能承载第 1 步；惊喜偏好/扫兴点/特别注意用 `Travel` 新增 `preferences Json?` 存 |
| 顶部 `1/5` 进度 + 右上「跳过」 | 多步流程的容错 | 进度点 + 「跳过」；任何一步都能跳，不阻塞建档 |

### S2 · 行程详情（截图：广州市7日游）

| 它做了什么 | 我们的落法（P1） |
|---|---|
| 大标题 + **「10.01至10.07 7天6晚」**（日期与天数是最显眼的副标题） | 详情页头部改成：旅行名 + `10.01 至 10.07 · 7天6晚`（`formatCompactRange` / `evaluateDateRange` 已有，直接复用） |
| **日期胶囊 tab**：`总览 | 10.01 周四 | 10.02 周五 | …`（可横滑） | 详情页改成 tab 结构：`总览 / 行程 / 相册 / 花销`，行程内再按天分片（横向日期胶囊） |
| 每天一个区块，行内「＋ 添加」 | `TravelTimeline` 的 DAY 卡片已有「记一笔 / 添加行程」，补「＋ 添加」行内入口与空态单行文案 |
| 右下悬浮主操作 | 详情页右下 FAB = **「＋ 记录」**（我们的主循环是"记"，不是"排"） |

### S3 · 添加抽屉（截图：添加至 10.01 周四）

| 它做了什么 | 我们的落法（P1） |
|---|---|
| 抽屉顶部：**「添加至 10.01 周四 ▾」**（先明确加到哪一天，可就地切换） | `ItineraryEditor` 顶部加"加到哪天"选择器，默认=当前天，可切 |
| 五个等宽入口：**导入地点 / 添加住宿 / 添加交通 / 从收藏夹 / 自定义** | 我们的抽屉做成**类型先选**：景点 / 餐厅 / 住宿 / 交通 / 活动 / 其他（`ItineraryEditor.tsx:18-25` 的类型已在），第一屏就是这 6 个大按钮 |
| 搜索框「搜索地点」+ 键盘态 | 先接 `data/cities.ts` 城市联想（已有 `suggestLocations`），POI 级搜索列为 P2（需要外部数据源） |
| 键盘弹起时抽屉/按钮跟着上移 | 复用 `components/mobile/BottomSheet.tsx` 的既有避让逻辑 |

### S4 · 新建旅行表单（截图：去哪? / 什么时候? / 名字 / 更多）

**我们的 `TravelComposerForm` 已经实现了这一屏的 ~80%**（目的地联想、自研区间选择、标题建议、更多折叠、可见性）。
所以"新建旅行全面重构"的正确解读是：**保留表单主体，补上入口 + 落地 + 向导化**，而不是推倒重写。
需要补的差异只有三处：① 可见入口（R1）；② 建完落地（R2）；③ 「更多」里补预算/偏好并把类型选择做成参考那样的大色块卡片。

## 4. 目标方案

### 4.1 移动端信息架构（重构后）

```
底部 Dock ──[首页][旅行][ ＋记录 ][旅行圈][我的]
                              └─ 有文字标签，点击=新建旅行

/travel（旅行记录）
 ├─ 页头：旅行记录 + [ ＋ 新建旅行 ] ← **新增可见按钮**（R1）
 ├─ 足迹地图卡片
 ├─ 最近旅途 海报流（补 localOnly「待同步」角标）
 └─ 空态：「记录第一次旅行」

/travel/new（新建旅行）
 ├─ 第 0 步（可选）：偏好问卷（同行者 → 惊喜偏好 → 特别注意，可跳过）   [P2]
 ├─ 第 1 步：去哪？（城市联想）
 ├─ 第 2 步：什么时候？（区间选择 + 共 N 天 M 晚）
 ├─ 第 3 步：名字（自动建议）+ 更多（类型/同行者/描述/可见性/预算）
 └─ 开始记录 → **建完直接进详情**（R2 修复：`travelDetailHref` + 本地兜底）

/travel/detail?slug=…（旅行详情 · 移动端 tab 结构）
 ├─ 顶栏：← 返回 ｜ 旅行名（截断） ｜ ⋯（编辑信息 / 分享 / 删除）
 ├─ 头部：旅行名 + 日期区间 + 共 N 天 M 晚 + 类型/同行者 + 封面
 ├─ Tab: [ 总览 ] [ 行程 ] [ 相册 ] [ 花销 ]
 │   ├─ 总览：封面/相册横滑 · 行程摘要（前 3 条）· 花销概览 · 最新回忆
 │   ├─ 行程：横向日期胶囊（总览 | 10.01 周四 | …）+ 时间轴条目
 │   │        （图标 + 标题 + 起止时间 + 地点 + 备注）+ 行内「＋ 添加」
 │   │        → 抽屉：先选类型（景点/餐厅/住宿/交通/活动/其他）+ 加到哪天 + 时间 + 备注
 │   ├─ 相册：**上传**（拍照/多选，一次 ≤9 张）+ 按天分组 + 设为封面 + 点击进沉浸查看器
 │   └─ 花销：预算 vs 已花 + 分类记账 + 合计 + 按天/分类汇总
 ├─ 底部主按钮：[ ＋ 记录一笔 ]（唤起 MemoryComposer：文字+照片）
 └─ 空态：一行字（"还没有记录"），不做插画（沿用 M6 原则）
```

**沉浸式全屏相册的去向（关键决策点，见 §8-2）**：
推荐保留这个能力，但把它**降级为二级页**：详情页「相册」tab 里点某张图才进入 `/travel/photos?slug=…&index=n`，
并给它加**关闭按钮**。默认落地的详情页必须是"能操作"的。

### 4.2 视觉与色彩

- 全部沿用现有设计系统：`app/mobile.css` 的 `--m-*` token（暖陶土 `#C67A4E`、米白 `#FFFBF7`、
  卡片 20px 圆角、`m-glass` 顶栏、`m-card` 卡片、44px 触控），**不引入第二套色板**。

  图标用现有 `lucide-react`（已有 `ItineraryChip` 的类型图标映射）。
- 跑 `node scripts/check-design-tokens.mjs` 保证不出现硬编码色值（仓库已有该门禁）。

### 4.3 数据模型判断

| 能力 | 结论 |
|---|---|
| 行程编排 | **不需要改 schema**（`TravelDay` + `ItineraryItem` 已在用） |
| 花销记录 | **不需要改 schema**（`Expense` 已在） |
| 花销**预算** | **需要**：`Travel.budget Float?`（推荐）或 `Travel.meta Json?`（更宽松但语义弱）。建议前者 + 一条迁移 |
| 偏好问卷 | **需要**：`Travel.preferences Json?`（`{ companionsStyle, delights: string[], vetoes: string[], cautions: string[] }`） |

| 地点/POI | `Location` 表在，但**没有**数据源与前台接口；POI 搜索列 P2 |

> 迁移注意：仓库里有 `scripts/apply-schema-migration.cjs` 的先例，新字段要走同一套。

## 10. 偏好问卷（第二轮已落地）

需求（用户拍板）：**新用户注册成功并登录时弹出一次偏好问卷；完成或跳过后，后续不再弹出。**

### 10.1 触发时机与「只弹一次」的实现

| 事项 | 方案 |
|---|---|
| 触发点 | 注册成功 → 首次登录落地页（`/`）渲染后，在**首启引导之后**检查一次 |
| 状态落库 | `User.preferences Json?` + `User.preferencesCompletedAt DateTime?`；跳过也算完成（写同一个时间戳，另存 `skipped: true`） |
| 为什么落库而不是 localStorage | 已有 `components/mobile/Onboarding.tsx` 用本地标记控制首启引导 —— 换设备/清缓存会再弹。问卷结果本身要用（新建旅行默认值），必须跟账号走 |
| 幂等 | 服务端 `PATCH /api/me/preferences` 仅在 `preferencesCompletedAt IS NULL` 时写入；客户端拿到 `completedAt != null` 直接不渲染 |
| 不阻塞主流程 | 任何一步都能「跳过」；跳过即写完成时间戳 |

### 10.2 题目（对齐参考产品截图，精简为 3 屏）

1. **同行者风格**（单选）→ 直接映射 `TravelType` 默认值：独自 / 和伴侣 / 和朋友 / 一家人
2. **惊喜偏好**（多选）：发现隐藏景点 / 认识新朋友 / 淘到心动好物 / 赶上特色活动（并入参考产品第 4 屏的「扫兴点」作为反向选项，少一屏）
3. **特别注意**（多选）：避免剧烈运动 / 容易晕车晕船 / 会带小朋友 / 会带宠物 / 需要无障碍设施 / 容易高反

### 10.3 结果的用途（否则收集了也没意义）

- 新建旅行表单：`travelType` 预选为问卷里的同行者风格；「更多」里提示注意事项
- 行程与推荐：命中「避免剧烈运动 / 容易高反 / 需要无障碍设施」时，在行程页签顶部给一行提示
- 不引入 AI，不做自动排程 —— 只做「默认值 + 提示」这两件确定有收益的事

### 10.4 改动面预估

- schema：`User.preferences` / `User.preferencesCompletedAt`（可空，零停机）
- 新增 `PATCH /api/me/preferences` + `GET /api/me` 下发字段
- 新增 `components/mobile/PreferenceSurvey.tsx`（复用 `ChoiceCard` / `SegmentedControl` / `Button`）
- 挂载点：首页客户端（与 `Onboarding` 同层；两者不要同时弹 —— 问卷让位于首启引导）
- 预估 **1–1.5 天**（含单测与 E2E 一条：注册 → 弹一次 → 跳过 → 刷新不再弹）

### 与 §10 设计的差异

| 设计 | 实际 | 原因 |
|---|---|---|
| 落 `User.preferencesCompletedAt` | 一致 | 换设备/重装不再弹，只有服务端字段能做到 |
| 3 屏（同行者 / 惊喜+扫兴 / 特别注意） | 一致 | 第 2 屏把参考产品的「扫兴点」并进来，少一屏 |
| 「只在首页弹」 | 一致（且必须等首启引导退场） | 深链首次打开不该被两个全屏模态堵住 |
| 桌面端 | **有意只在移动端弹**（`md:hidden`，与首启引导同策略） | 桌面是次级工作面；桌面上没做过问卷的用户，下次打开 App 会被问 |

### 踩坑记录（重要）

`GET /api/me` 返回的是 **`{ success, data: profile }`**（`lib/api-response.ts` 的 `ok()`）。
