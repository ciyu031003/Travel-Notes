## 2026-08-20 · 3.0b 静态导出诊断（发现架构卡点）

### 诊断结果
- 执行 `MOBILE_EXPORT=1 npm run build`（output='export'）：编译通过，但在「Collecting page data」阶段失败，首个报错为 `/api/admin/audit`。
- 报错本质：`output: 'export'` 与 API 路由（route handlers，约 60 个）不兼容——API 路由是服务端动态运行时，无法静态导出。

### 结论（如实）
- 「本地 webDir 静态壳」无法从「含 API 路由的同一个 Next.js 应用」直接导出。要实现真正的本地壳，需拆分架构：服务器保留 Next.js（API+SSR），移动端另建不含 API 的静态前端（复用 React 组件）打包进 www/。
- 当前 3.1-3.5 离线数据层（SQLite/媒体/同步）依赖 Capacitor 原生桥，只有本地壳（非远程 server.url）下才会激活。

### 待定方向（3 选 1，待用户拍板）
- A 拆分架构：API 服务器 + 独立移动端静态前端（正确但工作量大）。
- B PWA Service Worker 壳缓存：短期实现「断网开首页」，但原生离线层可能不激活。
- C 暂缓本地壳，先做 3.6 后台能力模块化（独立价值）。
